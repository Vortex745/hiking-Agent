# 徒步计划书导出约定

路线比较导出采用 `route_comparison_report` 协议（`schema_version=2.0`）。正文按新版计划书版式排为封面加 13 个编号章节：计划摘要、计划信息、路线摘要、行程时间线、交通住宿与联络、人员分工、费用预算、装备与补给、风险决策区、出发前检查、候选路线对比、排序说明和来源证据。

## 封面与计划状态

第 1 页是独立封面，只写状态不写正文：草案类型（`plan_type`）、审阅结论（工单 06 的规则结论）、安全门（工单 07 的拒绝记录）、路线核验、资料模式、生成时间与计划编号。封面只转述已经入库的记录：没有记录的项显示“待核验”，`generic_draft` 的副标题不得出现“已核验”。安全门记录目前只随事件载荷传递、尚无独立行，因此导出封面的该行仍为“待核验”。

## 内容边界

- 路线数值、天气、地图、开放状态和风险来自服务器核验证据，继续受既有证据与安全门约束。
- `report_export.plan_details` 只摘录用户明确给出的活动安排，包括日期、集合、人数、领队、交通住宿、应急联系、撤退安排、行程和预算；工单 06 的补充安排记录（`plan_arrangements`）在生成文档时合并覆盖草稿行，标签取自 `plan_workflow.ARRANGEMENT_FIELDS`。未知安排留空，PDF 显示“待确认”。这些安排不具有路线事实的核验状态。
- 预算条目只有 `BudgetItem` 会被合计；用户的预算自由文本原样成行，金额列仍为“待确认”，服务器端不解析、不估算、不合计未知项。
- 未提供分段行程时输出通用行程模板（时间线各段仍为“待确认”），不根据总耗时推算出发、折返或到达时刻。
- 装备、岗位职责、风险处置和检查清单为通用建议，出发前须由领队确认。未知事实显示“待核验”。
- 普通 artifact 导出使用 Markdown AST 排版，补齐缺失章节并标为草案，封面同样只标“通用草案 · 路线事实待核验”。该入口没有独立路线证据校验，不能宣称草案中的模型事实已核验。
- 没有核验素材时不插入装饰性地图或户外图片：全文档零位图，未核验的路线地图只是一行“待核验”。

## 排版与恢复

A4 纵向、中文字体、独立封面页、编号章节、续页页眉（第 2 页起）、页码和签字区。长表重复表头（时间线与候选对比均以渲染出的续页表头为验收证据），超长行允许分段；风险决策区整块移动，不从表格中间开始，并以红色标题、红色表头与红色底纹与普通绿色章节区分。两套排版共用 `computer.PLAN_SECTIONS` 一份章节词表：Markdown 入口按子串匹配标题别名，改名必须保留旧名别名，否则内容会静默落入上一章节。

路线报告从保存的 `ComparisonResult` 恢复，包括 `plan_details`。普通 artifact 在审批后才生成计划正文，effect 记录避免重复执行；正文生成失败时不会把原始请求导出为 PDF。

新增运行依赖：`mistune>=3.0,<4.0`，已登记在两份 requirements 中。
